## Goal
A hosted pilot can lose a disk, absorb a runaway user, and honour "delete my account" completely, and every time the
operator looks at a user's data there is a record of it. Required before anyone else's data is stored (PLAN.md 12).

## Prior art to check first
None found in career-ops (local files) or JobSync for multi-tenant hosting. Reuse Nexus's own Phase 2 work.

## What to build
1. **Backups.** A `backup` service under a `backup` compose profile in `docker-compose.yml` (pattern: the `caddy` and
   `portal` profiles): an official `postgres` image whose major version matches the Supabase project, running
   `pg_dump -Fc` daily from `SUPABASE_DB_URL` into a named volume and deleting dumps older than 14 days. Script in
   `scripts/backup/` (POSIX sh). `SUPABASE_DB_URL` is used in DEPLOY.md today but missing from `.env.example`: add it.
   `pg_dump` does not include Storage files (`portal-screenshots`); say so in DEPLOY.md and either back them up or
   state they are disposable. **Tested restore:** a script that restores the newest dump into a throwaway Postgres
   container and checks row counts for key tables; run it in the PR and paste the output (no data).
2. **Per-user limits.** Extend `src/lib/usage.server.ts` (`consumeUsage`, the `consume_usage` RPC from
   `20261006160000_usage_caps.sql`) with new kinds where a user can cost the operator: manual Gmail checks, portal
   tasks, job-link imports, CV uploads (size cap). Each kind gets an env var like `AI_DAILY_LIMIT`, empty = unlimited,
   listed in `.env.example`, DEPLOY.md and `dailyLimits` in `checkConfiguration` (`src/server/agentRunner.server.ts`).
   Widen the `UsageKind` type so the typecheck finds every caller.
3. **Logged admin access.** An append-only `admin_access_log` table (who, when, which user's data, why, which tool)
   with RLS on, no update/delete grants, and a `security definer` insert function callable only by `service_role`.
   `src/lib/adminAudit.server.ts` wraps any operator path that reads another user's rows with the service role. Grep
   `supabaseAdmin` uses to list today's paths (agent tick, Gmail push, sponsor import are system jobs, not admin
   access) and document in DEPLOY.md that direct SQL/dashboard access must be logged by hand, until a tool exists.
4. **Complete account deletion.** `deleteMyAccount` in `src/lib/account.functions.ts` misses tables today:
   `usage_counters`, `automation_jobs` (row `job_key = 'agent:<uid>'`), and `app_user_connections`, which is cleared
   only through `disconnectGmailForUser` (delete all the user's rows directly as well). Add them, and the new `admin_access_log` decision (keep as legal record or
   pseudonymise: owner question). Then add a guard: a test that lists every `public` table with a `user_id` column (or
   a user id in a key) from the replayed migrations and fails if `deleteMyAccount` does not cover it, plus every
   Storage bucket created in migrations (`portal-screenshots` today). Also note `exportMyData` omits
   `gmail_sync_state` and `usage_counters`; add them to the export (never `app_user_connections` ciphertext).

## Database
New migration for `admin_access_log` and any usage kind constraint; RLS on, revoke from `public`, `anon`,
`authenticated`. Extend `src/test/migrations.test.ts`; regenerate `src/integrations/supabase/types.ts` (`bun run db:types`).

## Tests

left for them and the other user untouched; the table-coverage guard above. `src/test/usage.test.ts`: new kinds.
Migration test: `admin_access_log` rejects update/delete and inserts from `authenticated`.

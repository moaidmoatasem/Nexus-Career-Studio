# 12.2 Data inventory, retention, breach runbook and AI-provider data list

**State:** gate-1 · **Needs:** Gate 1 ticked; 12.1 (legal advice) under way, since retention periods and notice duties come from it
**File area:** new `docs/privacy/` (`data-inventory.md`, `retention.md`, `breach-runbook.md`, `data-recipients.md`);
README.md and DEPLOY.md only for one link each
**Branch:** `agent/12.2-data-inventory` · **PLAN.md:** Phase 12, task 12.2

## Goal
Before anyone else's data sits on a server the owner runs, the owner can answer, from one place: what personal data
Nexus stores, where, why and for how long; who receives it (AI provider, Google, Firecrawl, Supabase); and what to do
within 72 hours of a breach (Egypt PDPL, GDPR/UK GDPR; see STRATEGY.md "Rules that shape the design").

## Prior art to check first
None found: career-ops is local-first and keeps no server inventory; JobSync has none. Write it for Nexus.

## What to build
Documentation only. Every row must be traceable to code: cite the file (and migration) for each entry, and grep
rather than guess. Re-check the lists below against `supabase/migrations/` and `src/` at the time of writing.
1. **`data-inventory.md`**, one row per store: table or bucket, personal fields, purpose, who can read it (RLS or
   service role only), source (user, Gmail, AI output), and where it is written. Current stores:
   - user-owned tables: `profiles`, `vault_items`, `applications` (incl. `tailored_pack`), `application_events`,
     `role_decisions`, `source_connections`, `discovery_runs`, `agent_settings`, `agent_activity`, `portal_tasks`,
     `unmatched_mail_messages` (sender, subject, snippet), `processed_mail_messages`, `gmail_sync_state`
     (`mailbox_email`), `app_user_connections` (AES-GCM encrypted Gmail refresh token, `src/server/appUserConnections.server.ts`),
     `usage_counters`, private `jobs` rows (`user_id` set);
   - service tables that embed a user id: `automation_jobs` (`job_key` = `agent:<user_id>`, `src/server/agentRunner.server.ts`);
   - shared, non-personal: catalog `jobs` (`user_id` null), `sponsors`, `sponsor_snapshots`, `sponsor_import_rows`
     (public Home Office register about organisations);
   - Storage bucket `portal-screenshots` (private, written by `worker/index.mjs`, may show personal form fields);
   - Supabase Auth (`auth.users`: email, sign-in metadata) and server logs (`console.error` calls can include mail or
     AI error text: `src/server/gmailSync.server.ts`, `src/lib/ai.server.ts`).
2. **`data-recipients.md`** (the AGENTS.md "record which providers receive which data" rule): for each outbound call,
   the data sent and the file. AI provider via `generateStructured` (`src/lib/ai.server.ts`): CV text in `extractVault`,
   Career Vault items plus the posting in `synthesizePack`, a pasted email in `classifyEmail` (all `src/lib/ai.functions.ts`), filtered
   recruitment mail in `src/lib/email-classifier.server.ts`, alert emails in `src/lib/alertLeads.server.ts`, pasted job
   text in `src/lib/jobText.server.ts`. Firecrawl (`src/lib/discovery.server.ts`): employer URLs and search queries
   built from target titles and locations. Google (`src/server/gmailApi.server.ts`, `src/routes/api/public/gmail-push.ts`).
   Greenhouse, Lever, Ashby (`src/lib/atsApis.server.ts`): posting ids only. Supabase: everything stored. Note which
   calls are deterministic-filtered first (mail, `src/lib/mailFilter.ts`) and that AI providers may sit outside Egypt
   (cross-border transfer).
3. **`retention.md`**: a period per store with `<owner sets>` placeholders, what deletes it today (account deletion in
   `deleteMyAccount`, `src/lib/account.functions.ts`; Gmail disconnect) and what has no deletion path yet (for example
   old `agent_activity`, `processed_mail_messages`, `usage_counters`, screenshots of finished tasks). List the purge jobs
   a later task would add; do not build them here.
4. **`breach-runbook.md`**: detect, contain (rotate `SUPABASE_SERVICE_ROLE_KEY`, `APP_USER_CONNECTION_KEY_SECRET` and
   what re-encryption means, `AGENT_TICK_SECRET`, AI and Firecrawl keys; revoke Google OAuth client secret), assess,
   notify the regulator within 72 hours and affected users, record. Leave regulator contacts as `<owner fills>`.
5. **Supabase region:** state the current requirement and leave the choice to the owner (PLAN.md 12.2).

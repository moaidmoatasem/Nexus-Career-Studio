# 10.4 Interface text in English and Arabic

**State:** gate-1 · **Needs:** 10.1 and 10.2 merged. Can run alongside 10.3. 10.5 and 10.6 come after it.
**File area:** `src/lib/i18n/**` (new), user-visible string literals in `src/routes/**` and `src/components/*.tsx` (not `src/components/ui`), `src/test/i18n.test.ts` (new)
**Branch:** `agent/10.4-translations` · **PLAN.md:** [10.4](../../../PLAN.md#phase-10-arabic-first-interface-gate-1)

## Goal
An Arabic-speaking user can run their whole search in Arabic: navigation and the main screens read naturally in Modern
Standard Arabic, while English stays exactly as it is.

## Prior art to check first
career-ops' Arabic modes: reuse their terminology for job-search and Gulf labour terms (for example end-of-service
gratuity, allowances) so both projects say the same thing. JobSync: none found.

## What to build
1. `src/lib/i18n/en.ts` (new): a nested `as const` object of every string, grouped by screen (`nav`, `today`, `discover`,
   `applications`, `connections`, `settings`, `common`). English is the source of keys.
2. `src/lib/i18n/ar.ts` (new): typed as `Messages` derived from `en` (same keys, `string` values), so a missing or extra
   Arabic key fails `bun run typecheck`.
3. `src/lib/i18n/index.ts` (new): `t(lang, key, vars?)` with `{name}` interpolation and a `useT()` hook reading `lang` from
   10.1's `LangContext`. Plurals through `Intl.PluralRules` (Arabic has zero, one, two, few, many, other) with keys such as
   `roles_count.one`; numbers and dates through `Intl.NumberFormat` / `Intl.DateTimeFormat` with the current language.
   No i18n library.
4. First PR: the infrastructure plus navigation (the `NAV` items and footer in `src/routes/_authenticated/route.tsx`), Today
   (`today.tsx`, "Mission Control"), Discover (`radar.tsx`), Applications (`applications.tsx`,
   `applications.$applicationId.tsx`), Connections (`connections.tsx`) and Settings (`settings.tsx`), plus the `head()`
   titles of those routes. Later PRs: the remaining routes and `src/components/*.tsx`, a few screens per PR.
5. Translate only interface text. Do not translate or alter user data, job postings, AI output or AI prompts
   (`src/lib/ai.functions.ts` stays as is). Keep product terms consistent (one glossary at the top of `ar.ts`).
6. Keep English labels byte-identical so `e2e/smoke.spec.ts` selectors still match.

## Tests
`src/test/i18n.test.ts` (new): `en` and `ar` have the same keys (runtime check too); no empty Arabic value; interpolation
placeholders match between languages; plural keys cover Arabic's categories where used; `t` falls back to English for an
unknown key only in development with a console warning.

## Goal
Visa logic is UK-only and spread across `scoring.ts`, `sponsorRefresh.server.ts` and the sponsor UI. Give it one interface per
country so that new countries (9.2, 9.3) are added as modules, not as `if (uk)` branches, as AGENTS.md requires ("country
specifics live in separate modules"). For UK users nothing visible changes in this task.

## Prior art to check first
career-ops `plugins/h1b-sponsor` (US) and the A.2 UK plugin built on it: reuse their result shape (register entry or
"unknown", never a guess) and naming. If career-ops already has a country-module interface, mirror it and say so in the PR.

## What to build
1. `src/lib/visa/types.ts` (new): `VisaModule` = `{ country` (ISO 3166-1 alpha-2), `label, source: { name, url, licence },
   notes: CountryNote[]`, `placeTerms` (for role-country detection), `checkEmployer(db, name): Promise<EmployerCheck> }`.
   `EmployerCheck` = `{ status: "listed" | "possible" | "not_listed" | "no_data", entry?, similarity?, sourceDate }`.
   `CountryNote` = `{ text, sourceUrl, sourceDate }`; no note without a source and date. Browser-safe: no server imports.
2. `src/lib/visa/uk.ts` (new): the UK module. `checkEmployer` calls the existing RPC `match_sponsor_company_v3`
   (`supabase/migrations/20261005154646_…sql`), using `isVerifiedSponsorMatch` from `scoring.ts` to split listed and possible;
   `sourceDate` comes from the active row in `sponsor_snapshots`. Move `UK_PLACE_TERMS`/`UK_COUNTRY_TERMS` here from `scoring.ts`.
3. `src/lib/visa/index.ts` (new): a registry (`VISA_MODULES`, `moduleFor(country)`) and `roleCountry(job)`, generalising
   `isUkRole` in `src/lib/scoring.ts` (the location wins over the stored country; keep the `NON_UK_PLACE_TERMS` behaviour). Keep
   `isUkRole` as a wrapper so `radar.tsx` and `data.ts` keep compiling unchanged.
4. `src/server/visa/refresh.server.ts` (new): an optional `refresh()` per module, server-only. Move `refreshSponsorRegister`
   behind it (keep `src/server/sponsorRefresh.server.ts` as a re-export or delete it after updating imports). In
   `agentRunner.server.ts` loop over modules with a refresh, each with its own `claim_automation_job` key (UK keeps
   `sponsor_refresh`).
5. `src/lib/scoring.ts`: `calculateFitScore` takes the role's country and the module's `EmployerCheck` status instead of a UK flag.
   If 5.1 has merged, build on its `visa_needed_countries` / `visaNeededFor` instead of `requiresVisa`. Keep `visaCheck: "uk_sponsor"` for UK and `"not_applicable"` otherwise, so stored packs still read; scores must not change.
   Scoring stays pure and deterministic.
6. `src/lib/sponsor.functions.ts`: `checkSponsorRegister` delegates to the UK module.

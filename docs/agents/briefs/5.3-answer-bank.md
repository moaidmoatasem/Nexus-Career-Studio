## Goal
The user writes, once, their own answers to the questions application forms keep asking: notice period, expected
salary per currency, right to work and visa status per country, relocation, availability and links. Wherever Nexus
helps with a form (today the portal assistant; later application kits in 6.1 and the extension in Phase 7) it shows
these answers to copy, and shows "not answered yet" when one is missing. Nexus never writes, guesses or generates an
answer: the automation policy (STRATEGY.md) allows visa, salary and legal answers only from the user's own bank.

## What to build
1. **Question catalog** (`src/lib/answerBank.ts`, new): a typed list of keys with labels and scope: `notice_period`,
   `availability_date`, `expected_salary` (per currency), `right_to_work` and `visa_status` (per country), `relocation`
   (per country, optional), `link_portfolio`, `link_linkedin`, `link_github`, `link_other`, and `custom` (user-written
   label). Labels are plain, role- and country-agnostic; no country rule lives here (Phase 9 owns `src/lib/visa/`).
2. **Selector** (same file, pure): `answersForRole(bank, { country, currency })` returns, per key, the user's answer for
   that country or currency, a country-free answer as fallback, or `missing`. It never derives one answer from another
   (no currency conversion, no "UK right to work" implied by citizenship, no salary from the posting).
3. **Never generated**: answers enter only through the user's own form. No server function, AI prompt, Gmail sync or
   worker writes to `answer_bank`. Answers are not sent to any AI provider in this task. Add a test that greps `src/` and
   `worker/` so only `answers.tsx` and `account.functions.ts` reference the table (extend the list when 6.1 and Phase 7 do).
4. **UI** (`answers.tsx`, new, sidebar link "Answer bank"): grouped by key; add an answer per country (ISO 3166-1 alpha-2,
   `/^[A-Z]{2}$/` or the picker from `src/lib/countries.ts` once 5.1 is on `main`) or per currency (ISO 4217); free text;
   "last updated" per answer, since stale salary or visa answers are risky. Works on a phone. A `useAnswerBank()` hook.
5. **Portal assistant** (`PortalAssistant.tsx`): below "Verified fields to paste", an "Your answers" list from
   `answersForRole` for the job's `country` (and the currency in `salary_range` only if the user has an answer in that
   currency). Missing ones link to the answer bank. Nothing is filled automatically.
6. **Worker unchanged**: `worker/adapters.mjs` keeps refusing `SENSITIVE` fields; answer-bank filling belongs to the
   extension (Phase 7), not the server-side helper.
7. **Data export and delete** (`src/lib/account.functions.ts`): add `answer_bank` to `OWN_TABLES` and the delete list.

## Database
New `supabase/migrations/<yyyymmddhhmmss>_answer_bank.sql`: `answer_bank` with `id`, `user_id`, `question_key text`
(check: the catalog keys), `label text not null default ''` (required for `custom`), `country text` (null or `^[A-Z]{2}$`),
`currency text` (null or `^[A-Z]{3}$`), `answer text not null` (length 1–2000), `created_at`, `updated_at` with
`set_updated_at`. Unique index on `(user_id, question_key, coalesce(country,''), coalesce(currency,''), label)`. RLS, grants
and index like `role_decisions`; `service_role` read is enough for later server use. No backfill: no existing data holds
user answers, and none may be inferred from `profiles` (for example `requires_visa`).
Regenerate types with `bun run db:types` (or hand-edit and say so in the PR).

## Goal
A user can keep several searches (for example "Product designer, remote EU" and "UX lead, Dubai") instead of one set of
targets on `profiles`. Discovery, **Find roles now** and fit scoring take a search profile as input, and nothing in that
path assumes one profession or one country. This is the base for the daily queue per profile (6.1).

## What to build
1. **Countries module** (`src/lib/countries.ts`, new): ISO 3166-1 alpha-2 codes with English names, `isCountryCode()`,
   and a small picker list. No visa or market logic here (that is Phase 9, `src/lib/visa/`). 5.3 may import it.
2. **Pure helpers** (`src/lib/searchProfiles.ts`, new): the zod schema for a profile; `isExcludedRole(profile, job)` moved out
   of `refreshMyDiscovery` (excluded companies and keywords, same matching as today); `buildDiscoveryQuery(profile)` built
   from the profile's titles, keywords and locations (keep today's `site:` filters for Greenhouse, Lever, Ashby and
   Workday; never a job-board host, see `src/lib/jobSources.ts`); `visaNeededFor(profile, job)`.
3. **Scoring** (`src/lib/scoring.ts`): `scoreRole` takes `search` (domains, `visa_needed_countries`) next to `profile`
   (years of experience stays on `profiles`: it describes the person). `requiresVisa` becomes "the role's country is in
   `visa_needed_countries`"; the UK sponsor check applies only when that country is `GB` and `isUkRole(job)`. Other countries
   score as `not_applicable` until Phase 9 adds data. Callers: `synthesizePack` in `src/lib/ai.functions.ts` (one-line change:
   load the user's default profile), `radar.tsx`, `InsightsPanel.tsx`. Scores must stay identical for backfilled users.
4. **Find roles now** (`refreshMyDiscovery`): input `{ searchProfileId }` (default profile when absent); query from
   `buildDiscoveryQuery`; exclusions from `isExcludedRole`; record the profile on `discovery_runs.search_profile_id`.
   Keep one Firecrawl search per click and `FIRECRAWL_DAILY_LIMIT` (`src/lib/usage.server.ts`) as today.
5. **UI**: new `searches.tsx` route (list, create, edit, duplicate, delete, set default) linked from the sidebar in
   `src/routes/_authenticated/route.tsx`; remove the titles/locations/domains/visa inputs from `vault.tsx` (name, headline
   and years stay) with a link to the new page; a profile picker next to **Find roles now** in `radar.tsx`; `today.tsx` and
   `SetupProgress.tsx` check "has at least one profile with a title" instead of `target_titles`.
6. **Remove single-market defaults**: grep for `"UK"`, `GB`, `£`, `requires_visa` and hard-coded titles. In a new migration set
   `jobs.country` default to `''` and `profiles.requires_visa` default to `false`; make `isUkRole` treat an empty country as
   "not known" only when the location also says nothing (add tests; existing rows keep `'UK'`). Do not delete the seeded
   demo catalog in the first migration (applications cascade from it); ask the owner instead.
7. **CV variant link** (after 5.2 merges): `search_profiles.cv_variant_id` (FK to `cv_variants`, on delete set null) and a
   picker in `searches.tsx`. 5.2 does not touch `search_profiles`.
8. **Data export and delete** (`src/lib/account.functions.ts`): add `search_profiles` to `OWN_TABLES` and to the delete list.

## Database
New `supabase/migrations/<yyyymmddhhmmss>_search_profiles.sql` (never edit old ones). `search_profiles`: `id`, `user_id`,
`name`, `is_default bool`, `target_titles text[]`, `keywords text[]`, `domains text[]`, `seniority text` (check: `any`,
`entry`, `mid`, `senior`, `lead`, `executive`), `countries text[]` (ISO codes), `locations text[]` (free-text cities or regions),
`remote_preference` (same check as on `profiles`), `salary_min int`, `salary_currency text` (ISO 4217, `^[A-Z]{3}$`),
`visa_needed_countries text[]`, `excluded_companies text[]`, `excluded_keywords text[]`, `discovery_frequency` (same check as on
`profiles`), timestamps with the `set_updated_at` trigger. Partial unique index: one `is_default` per user. RLS, grants and
index exactly like `role_decisions`. Add `discovery_runs.search_profile_id uuid` (on delete set null).
Backfill: one profile "My search" per `profiles` row with any target, copying `target_titles`, `target_locations` → `locations`,
`target_domains` → `domains`, `remote_preference`, `salary_floor` → `salary_min` (currency null), `excluded_employers`,
`excluded_keywords`, `discovery_frequency`, and `visa_needed_countries = '{GB}'` when `requires_visa` (keeps today's scores).
Leave the old `profiles` columns in place and stop reading them; a later migration drops them after the owner agrees.
Regenerate types with `bun run db:types` (or hand-edit and say so in the PR).

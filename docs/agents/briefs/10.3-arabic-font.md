# 10.3 Self-hosted Arabic font

**State:** gate-1 · **Needs:** 10.1 merged; 10.2 merged (both may touch `src/styles.css`). Can run alongside 10.4.
**File area:** `src/styles.css` (font tokens), the font `<link>`s in `head` of `src/routes/__root.tsx`, `package.json` / `bun.lock`, `src/test/fonts.test.ts` (new)
**Branch:** `agent/10.3-arabic-font` · **PLAN.md:** [10.3](../../../PLAN.md#phase-10-arabic-first-interface-gate-1)

## Goal
Arabic text is set in a proper Arabic typeface that ships with the app, so it looks right and loads without contacting any
font CDN, and English keeps its current look.

## Prior art to check first
None found in career-ops or JobSync for a web UI.

## What to build
1. Add one `@fontsource` package (the owner picks: IBM Plex Sans Arabic or Noto Sans Arabic; prefer the variable build
   `@fontsource-variable/…` if available) with `bun add`. Import only the weights used (400, 500, 600, 700) and only the
   `arabic` subset CSS where the package splits subsets, from `src/styles.css` or the root route, so Vite bundles the files.
2. `src/styles.css`: today `--font-sans` is `"DM Sans", …` (around line 42) and there is a `--font-display` for headings. Add
   `:root:lang(ar)` (or `html[lang="ar"]`) overrides that put the Arabic family first for both tokens, with the Latin family
   as fallback for embedded English words. Adjust line height for Arabic only if needed (for example `leading-relaxed` on
   body text), never for English.
3. Fonts must not download for English users: rely on `@font-face` `unicode-range` from fontsource and check in the
   browser's network tab that no Arabic font file loads on an English page.
4. Note in the PR: `__root.tsx` (around lines 89–93) still loads DM Sans, Space Grotesk and JetBrains Mono from
   `fonts.googleapis.com`. PLAN.md says "no font CDN"; propose moving those to `@fontsource` too (same task if the owner
   agrees, see below) and dropping the `preconnect` links.
5. Leave `.ats-paper` (the CV preview, which names "Amiri") to 10.6.

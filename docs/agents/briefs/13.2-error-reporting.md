## Goal
An instance owner who sets `SENTRY_DSN` sees server and browser errors in Sentry or a self-hosted GlitchTip, so
failures on a deployed instance are noticed without reading container logs. With it unset nothing changes and no
request leaves the server. It replaces the Lovable error reporter that was removed.

## Prior art to check first
None found in career-ops (local CLI) or JobSync for this. Reuse the existing capture points: `src/lib/error-capture.ts`
(wraps `console.error`, keeps the last error), `src/server.ts` (catches h3-swallowed SSR errors), the `errorMiddleware`
in `src/start.ts` and `ErrorComponent` in `src/routes/__root.tsx`.

## What to build
1. **No SDK unless it fits the rules.** AGENTS.md forbids Node built-ins in server code and vendor build plugins, and
   the server must run on Node and edge workers. Prefer a small sender that posts an event to the DSN's envelope
   endpoint with `fetch` (parse `https://<key>@<host>/<project>`; the same protocol works for GlitchTip). If an SDK is
   used, it must be a runtime-agnostic package with no Vite/Sentry build plugin and no source-map upload step; justify
   the choice in the PR.
2. **Off when unset.** `SENTRY_DSN` (server) and `VITE_SENTRY_DSN` (browser, build-time, optional; it is public by
   nature) are read once; blank means disabled and no code path calls the network. Optional `SENTRY_ENVIRONMENT`.
3. **Scrub personal data before sending** (shared pure function in `src/lib/errorReport.ts`): no request bodies, no
   cookies or `authorization` headers, no query strings, no user email or name; replace email addresses, bearer
   tokens, JWT-looking strings and UUIDs in messages and stack frames; user id only as a salted hash or not at all; cap
   message length. Error text can contain mail subjects or CV text (for example `console.error` in
   `src/server/gmailSync.server.ts` and `src/lib/ai.server.ts`), so send only the error type, a scrubbed message and the
   stack. This is AGENTS.md's personal-data rule: send providers only what a task needs.
4. **Wire it in:** server errors from `src/server.ts`, `src/start.ts` and the agent tick failure path; browser errors
   from `ErrorComponent` and a `window` `error`/`unhandledrejection` listener added only when `VITE_SENTRY_DSN` is set.
   Reporting must never throw or delay the response (fire and forget with a short timeout).
5. **Config surface:** `errorReporting: has("SENTRY_DSN")` in `checkConfiguration` so `/api/public/health` shows it;
   add the variables to `.env.example` and a short DEPLOY.md section (Sentry or GlitchTip, what is sent, what is
   scrubbed). Record Sentry/GlitchTip as a data recipient in the 12.2 inventory if that doc exists.
